# CarciniScript plan

CarciniScript compiles a practical subset of Rust to ES modules, with v3 source maps, synchronously,
in the browser, at runtime. The first consumer is Bitburner (`.rs` scripts), following the same
integration shape as RapydScript-NS (`.py` scripts) in `bytburner-src`.

> *Carcinisation*: the tendency of evolution to keep producing crabs. Every language eventually
> becomes Rust.

Finished work is recorded in [FEATURES.md](FEATURES.md) (what compiles) and
[RUST_GAPS.md](RUST_GAPS.md) (where behavior differs from rustc); this document keeps the design
decisions and the open work.

## Contracts inherited from the RapydScript integration

| Concern | Python (RapydScript-NS) today | CarciniScript |
|---|---|---|
| Compile call | `web_repl().compile_mapped()`, sync, pure JS | Sync after one async `init()` (same as `@swc/wasm-web`) |
| Output | ES module, `export async function main(ns)`; evaluator rewrites `import` specifiers to blob URLs | Same |
| Runtime library | Baselib injected once onto `window` (`ρσ_*`) | Prebuilt runtime installed once on `globalThis.κσ` |
| Source maps | v3 JSON from compiler mappings, inlined by `NetscriptJSEvaluator` | Same; no evaluator change |
| Cross-file imports | `buildPythonVirtualFiles()` → `{ "dir/mod": code }` | Same with `.rs`; the type checker needs other files' signatures |
| RAM cost | `parseAST()` compiles then acorn-parses the JS | Same, so output must keep literal `ns.hack(...)` member calls |
| Editor | `registerRapydScript(monaco)` + `addDts(netscriptDefinitions)` | `registerCarciniScript(monaco)` + generated `ns.rs` bindings |

## Why not real rustc → wasm

- rustc + sysroot is hundreds of MB; compiles take seconds.
- Every NS call returns a Promise. Wasm can only block on one via JSPI, which is not universal.
- Bitburner's RAM calculator needs a JS AST.
- Wasm debugging needs DWARF tooling; JS + source maps just works in devtools.

## Architecture

```
carciniscript/
  compiler/src/      Rust crate → wasm-bindgen
    macros, mbe, *_prelude.rs, bundled, alias, modflat, nested, ..   pre-passes and source rewrites
    typeck*.rs, adt, bindings   whole-function inference + checking against bindings/*.rs
    moves, nll*.rs              move checking and the NLL borrow checker
    codegen*.rs, sourcemap      HIR/AST → JS text + mapping records → v3 JSON
    service, nav, std_docs, jsx_service   hover, completions, signature help, navigation
    memo                        result caches for the editor's repeated analyses
  bindings/ns.rs     NS surface, generated by tools/dts2rs.mjs from NetscriptDefinitions.d.ts
  bindings/js.rs     JS globals (DOM, JSON, Math, timers, fetch, ..)
  runtime/rt.js      Option/Result, iterators, collections, fmt, panics, React helpers
  tools/             build, dts2rs, native differential runs, the corpus survey
  test/              fixtures + differential tests (native rustc vs node), NS mocks, React, procmacro
  web-repl/          browser REPL and self-test
  docs/RUST_GAPS.md  counterpart to RapydScript's PYTHON_GAPS.md
```

**Parser: `ra_ap_syntax`, not `syn`.** syn stops at the first error, which makes for poor editor
diagnostics. ra_ap_syntax recovers, keeps byte ranges, and covers the full grammar. Its API churns,
so the version is pinned.

**Types are the hard part.** Unlike Python, Rust semantics depend on static types:
`7 / 2` is integer division for `i32`, float division for `f64`, and JS can't tell `4` from `4.0`
at runtime. Method resolution, `.into()`, `Default::default()` and `{}` vs `{:?}` all go through
types. Function signatures are always annotated, so local bidirectional inference is tractable.
We check against the std surface the checker models, Rust-source preludes compiled in when used,
and the generated `ns.rs`; we do not use `ra_ap_hir` (needs the whole std source, unstable API).

## Lowering decisions

See [FEATURES.md](FEATURES.md) for the per-feature chart. The load-bearing decisions:

- **Borrows and lifetimes** are erased in codegen. Exceptions: `&mut` taken on a primitive local
  boxes that local into a cell; `Copy` structs are cloned on assignment and by-value passing.
- **Integers:** `i8..i32`/`u8..u32` wrap (`|0`, `>>>0`, masks). The 64-bit kinds (`i64`/`u64`,
  `usize`/`isize`) are JS numbers, exact to 2^53: `+ - *` are plain, bit operations and shifts go
  through BigInt past 32 bits and wrap to 64, and nothing else wraps at 2^64 (a `u64` is what a
  player reaches for, and a number is 10x a BigInt). Only `i128`/`u128` are BigInt, wrapped to
  their width; that is where exact 64-bit hashes and generators go. Integer `/` truncates and
  panics on zero; JS `%` already matches Rust's truncated remainder.
- **Option:** `None` is `null`, `Some(x)` is `x`; `Some(None)` (per depth) and `Some(())` are markers (`κσ.$some` / `$unsome`).
  The NS boundary is free: `undefined` results read as `None`.
- **Result:** tagged object; `?` is an early return.
- **Panics** throw an `Error` named `panic` (`κσ.CarciniPanic`) whose message is `file:line:col: message`, the location baked in at compile time.
- **Structs/enums:** structs → classes with all `impl` blocks merged; field-less enums → numbers;
  data enums → tagged objects; `match` → decision chain.
- **Collections:** `Vec` = JS `Array`; `HashMap`/`HashSet` = runtime class with structural key
  hashing for tuple/struct keys; iterators = lazy runtime adapter class.
- **Strings:** JS strings; `len()` and byte-range slicing go through UTF-8 helpers.
- **Async:** `pub async fn main(ns: NS)` → `export async function main(ns)`; `.await` → `await`.
- **`println!`** → `console.log`. Modules are cached across scripts, so there is no single `ns` to
  print to; scripts should use `ns.tprint(&format!(..))`.
- **Modules:** each `.rs` file is a module; `use crate::a::b::item` → `import { item } from "a/b"`.
- **Runtime names** live under `κσ` so none collide with NS function names in RAM calculation.

## Borrow checking (static, in the compiler)

Borrowing and lifetimes are compile-time concepts; the emitted JS is identical either way.
Erasing them only means programs rustc would reject still run. What runs:

- **Move checking** (`moves.rs`): use after move, partial moves and definite initialization by
  init/move dataflow over the CST; its `move_sites` also drive `Drop` codegen.
- **NLL** (`nll.rs`, `nll_lower.rs`, `nll_rty.rs`, `nll_std.rs`, `nll_bir.rs`): rustc's shipping
  borrow checker is NLL, not Polonius, and NLL is intra-procedural, so each function is checked on
  its own. It is an overlay on the erasing compiler: a per-function IR with places and a CFG,
  reference-aware local types rebuilt from annotations, signatures, struct fields and a std borrow
  table, liveness-based region inference with universal regions for the signature's lifetimes,
  two-phase borrows, reborrows, closures as separate bodies over captured places (RFC 2229 field
  paths), temporaries with `let` lifetime extension and constant promotion, implied bounds, deref
  coercion, and E0499 / E0502 / E0503 / E0505 / E0506 / E0597 / E0515 / E0716 / "lifetime may not
  live long enough" with rustc's wording. Conflicts are errors, as in rustc;
  `setStrictBorrows(false)` makes them warnings. Generated code (derive expansions, bundled crate
  preludes) is skipped. Unknown shapes (a generic `T` instantiated with a reference, methods of
  other modules and of bundled crates, closures' return types outside std's closure-taking
  methods) default to owned: silence, never a false positive. `NLL_DUMP=1` prints every body's IR
  and `NLL_TIME=1` the checker's time (native builds).

Left out, deliberately: Polonius location sensitivity, `for<'a>`, `dyn Trait + 'a` object
lifetime defaults, drop-check subtleties (`#[may_dangle]`), `T: 'a` well-formedness on struct
definitions, `impl Trait` capture rules (treated as capturing everything), and per-function result
caching (the file-level memo covers the editor's repeated analyses; the checker is about 1 ms on
the largest Bitburner script). `async` bodies are checked as if synchronous (`.await` is a call),
which matches rustc for non-`Send` futures. If the overlay's duplicated method resolution becomes
the dominant maintenance cost, the fallback is a `Ty::Ref` in the type checker, erased at codegen.

**Test oracle.** Every corpus file rustc accepts must produce zero borrow errors, so
`npm run corpus` is a false-positive counter. `test/run.mjs` holds programs rustc rejects (each
confirmed against rustc) with the expected message and position, and programs rustc accepts that
must stay quiet. Keep rustc's exact wording, since the editor shows it.

- [ ] Optional debug mode: RefCell-style runtime guards on collections (mutate-while-iterating
  panics instead of silently misbehaving).

## NS bindings

`tools/dts2rs.mjs` uses the TypeScript compiler API on `NetscriptDefinitions.d.ts`:
`number` → `f64`, except whole numbers → `i32` (TS has one number type, so `isWholeNumber` picks
them out by name: threads, pids, ports, cores, levels, counts, indexes, Go / Stanek coordinates,
with an explicit `Owner.member` list for the rest; money, RAM, time, rates, multipliers,
reputation, hashes and shares stay `f64`, and so does anything that can be `Infinity`, like
`getActionCountRemaining`), `string` → `String`, `T[]` → `Vec<T>` (parameters borrow: `&str`, `&[T]`, since
no NS function changes or keeps a string or array it's given), optional / `T | undefined` → `Option<T>`,
`Promise<T>` → `impl Future<Output = T>`, interfaces → extern structs (with `#[extends = ".."]`
for `interface X extends Y`), tuples → `[T; N]` / `(A, B)`, `Map` / `Record` → `HashMap`, inline
object results and `Named & { .. }` intersections → structs of their own, `ReactNode` →
`react::Node`, `any` → `JsValue` (wasm-bindgen's, with `as_string()` and friends; a `JsValue`
parameter takes any value). Scripts can name the interfaces and build the option ones
(`RunOptions { .., ..Default::default() }`). Bitburner regenerates its copy with
`npm run generate:rust-bindings`, and a jest test fails when it's stale.

**Unions are enums that view the JS value.** A d.ts union is a Rust enum named after the TS type
(`ScriptArg`, `FilenameOrPID`, `PlayerRequirement`, `Task`, `SleeveTask`, `NsResult`, one struct
per coding contract), so hover and `match` exhaustiveness say exactly what can be in it, and the
name is the one in Bitburner's NS docs. The value at run time is the JS value itself
(`Repr::Js`): `match` lowers to `typeof` / `Array.isArray` tests for primitive unions and to a tag
field compare (`v.type === "money"`) for tagged ones, nothing is converted at the boundary, and
`ns.args` keeps identity. A union parameter also takes any variant's payload directly, so
`ns.run("x.rs", 4, "n00dles")` doesn't change. `JsValue` stays only where the d.ts says `any`
(port data, `codingcontract.getData`, `dynamicImport`, `flags`, `print` / `tprint` arguments).

**String-literal unions** (`CityName`, `CorpEmployeePosition`, `GymType`, ..) are `String`
(decided 2026-11-20). A Rust enum per union (`CityName::Aevum`, its value the string) would show
the valid values too, but would break `"Aevum"` literals unless those parameters also took a
`&str`, and `ns.enums` already lists the values.

## Source maps

The codegen writer tracks output line/column and records a mapping at each statement and
expression back to the Rust byte offset, converted to line + UTF-16 column. The `sourcemap` crate
encodes v3 JSON. Bitburner's existing inlining in `NetscriptJSEvaluator.ts` is unchanged.

## Real-world corpus survey

Every `.rs` file in the local cargo registry (230 crates, 5,220 files after dropping parser and
compile-fail fixtures) is compiled file by file, and each error is sorted into "missing crate or
module", "thread", "std library", or "language". Errors from names in other crates or other files of
the same crate, and from threads, `Arc`, `Mutex` and atomics, don't count. Unresolved names don't
hide later errors, so this is a fair per-file check. To run it: `npm run corpus` (about 5 minutes;
results in the OS temp dir). Its three steps:
- `tools/corpus-classify.mjs [root] [out.jsonl]` compiles each file and sorts each error (another
  crate or file, thread, std, language, parse, or uncategorized), with its byte range. A crate's
  own types and traits with std names (`syn::Path`, anyhow's `Chain`) don't count as std ones.
- `compiler/examples/corpus_ast.rs` parses each file with rust-analyzer's parser and adds the
  Rust features it uses (about 90 syntactic detectors, so a feature counts even where an
  unresolved name stops the compiler first), the construct each error is on, and the names
  from other crates or files in that construct, its statement, its function's signature
  (parameters, return type, generic bounds, `where` clause) and its `impl`'s header (self type
  and bounds). A name counts as from elsewhere when it is capitalized and the file doesn't
  define it, when a non-std `use` brings it in, or when it is a module path whose root the
  file neither declares nor imports from std (`anstream::AutoStream`, `fmt::Builder`). Each
  feature has a probe program (all accepted by rustc, 2021 edition); a feature whose probe
  doesn't compile is missing. `--probes` prints just those results.
- `tools/corpus-report.mjs` reclassifies an uncategorized error as downstream of another crate
  or file when such names are involved, or as a language gap when it's on a missing feature
  or is a `#[cfg]`'d item defined twice, then prints the verdicts, language gaps, every feature
  with its use and probe result, what's still uncategorized by message and construct, and the
  crates that pass in every file, and writes a per-file CSV.
- `tools/corpus-uncategorized.mjs` (optional, after the report) sorts what the report leaves
  uncategorized into finer buckets: by message, construct and a look at the source file (is the
  method, type or trait the error names defined in this file? is the error inside a macro
  expansion?), so each bucket says whether it is a real gap or downstream of another file. The
  "Still uncategorized" list below comes from it; re-run it after a survey to refresh the list.

The classifier keys on the compiler's message wording, so a reworded diagnostic silently moves
its files into "uncategorized" (the 2026-11-22 run found `the standard library function ..`,
`the iterator adapter ..` and `failed to resolve ..` that way, 800 files' worth). When the
uncategorized count jumps, check the report's top messages before reading anything else into
the numbers.

**Latest run** (2026-11-22, working tree after `d437860`, same registry as before): language
features all supported in **82.9%** of files (4,327 of 5,220; 81.8% on 2026-11-17, 67% at the
first run on 2026-11-16); counting std gaps, 70.5%; by lines, 67.0%. 839 files have a language
gap (650 of them unsafe/memory, 126 `union`, 58 proc-macro API, 67 `extern`: not planned), 647
are std-only, 48 have only uncategorized errors. 75 crates pass in every file; 156 in 80% or
more. Every one of the ~90 feature probes compiles. The std-only and language-gap counts are up
on 2026-11-17 because the classifier was taught the compiler's newer wordings (see above):
`size_of` / `ptr::*` paths now count as unsafe/memory and `the standard library type ..` as std,
where the 2026-11-17 run had them as "only external names". The crash sweeps (registry 5,922
files, std 3,004) last ran on 2026-11-17 with 0 panics.

**Not planned:** raw pointers and their methods (`as_ptr`, `as_mut_ptr`, `get_unchecked`,
`set_len`), `transmute`, `MaybeUninit`, `alloc`, `union`, `extern` blocks and their items, the
proc-macro API outside a proc-macro crate, `asm!`, `is_x86_feature_detected!`. JS values have no
memory layout. Also not planned: `super::` at the top of a module file (each file compiles on its

## React and `jsx!` (for `ns.printRaw` / `tprintRaw`)

Bitburner scripts draw tail windows and terminal widgets with React 17 (`React` and `ReactDOM`
as globals). CarciniScript parses with rust-analyzer's parser, so a bare `<div>` would break the
IDE features and the rustc checks of the corpus; markup lives in a macro instead, as Yew's
`html!` and Leptos' `view!` do. `jsx!` is a source rewrite (like `json!`) into calls of a bundled
`react` crate (`compiler/src/react_prelude.rs`: an opaque `Node`, `h`, the hooks with Rust
signatures, `κσ.$react` underneath), so the embedded expressions are type-checked,
borrow-checked and compiled as ordinary Rust. Text is quoted (Rust's lexer drops whitespace and
breaks on `don't`), a tag bound in scope to a fn or closure is a component, `style="color: red"`
becomes an object at compile time, and `dts2rs` maps `ReactNode` to `react::Node`. The corpus'
rustc stub has `jsx!` as a `macro_rules!` taking any tokens. Tests: `npm run test:react` (each
fixture has a `.jsx` twin compiled by TypeScript; both render under React 17 in jsdom and the
transcripts must match).

## Performance

Measured on node 24 (`--cpu-prof` keeps the wasm's function names), 2026-11-16 to 18. Compile:
`corpus/bitburner/darknet.rs` (784 lines) 78 ms cold and 0.7 ms for the same text again
(`memo::cached`, keyed by text, file name, bindings generation, settings and every resolved
file); hover, completions and signature help on an unchanged file 0.3 ms, and after an edit one
analysis serves all three. Bundled-crate preludes are parsed once per thread and trimmed to the
items the program reaches (`prune.rs`): `use chrono` with `NaiveDate` and `println!` is 25 ms.
Run time: the common Bitburner shapes (BFS over a `VecDeque` ring buffer, `BTreeSet` queues, byte
scans over strings, `&mut` to a place, slice views, composite map keys, inline 64-bit wrapping)
are within a small factor of a hand-written JS loop; plain map/filter/sum chains are about 1.3x
one. `for i in 0..n` and reversed ranges are plain `for` loops, `?` and panics are returns and
throws (try/finally only for `Drop` types), `push_str` is `+=`.

- [ ] Merging the read-only pre-pass rewrites into one walk; the remaining cost in chrono's
  formatter (`__chrono_format` handles every specifier, so `{}` on a date reaches `NaiveTime`,
  `TimeDelta` and `Weekday`).
- [ ] `match` as a `switch` on `$tag` (the `else if` chain is cheap once the subject is a name,
  so not pressing); skipping a `Copy` struct's clone at its last use; unit-variant singletons
  (blocked: `*r = Dir::E` through a `&mut` is `κσ.$replace`, which rewrites the object in place,
  so a shared instance would change every holder); named `Result` / tuple fields (no measured win
  yet, and tuples are arrays everywhere).
- [ ] Generic traits on numbers through `$dcall`: the rest/spread and `.call` are the cost, not
  the registry scan (a per-site cache was slower). Left as is unless a shape shows up.

## Risks

- **Type inference scope creep:** iterator chains with closures need generic inference over std
  signatures. Keep the std surface small and grow on demand.
- **Silent divergence:** `Copy` structs, `&mut` primitives, UTF-8 vs UTF-16, `i64` precision.
  Every one goes in `RUST_GAPS.md`.
- **The borrow checker sees through erased types only as far as its overlay reaches:** what it
  can't follow is silent, so some programs rustc rejects still run (what it does see is an
  error, as in rustc). Documented in RUST_GAPS "Type checking".
- **ra_ap_syntax churn:** pinned version; upgrades are deliberate.
